# Задание 8. Выявление и устранение «горячих» шардов

## Решение

### Вручную
Если метрики еще не готовы, то можно провести диагностику вручную
sh.status() - общее состояние базы
db.products.getShardDistribution() - распределение данных коллекции продуктов

db.adminCommand({ balancerStatus: 1 }) - проверка работы балансировщика
sh.balancerCollectionStatus("shop.products") - сбалансирована ли коллекция

db.currentOp({ active: true }) - получить текущие запросы

### Метрики
Набор метрик для отслеживания состояния шардов:
- Получение количества шардов и распределения данных sh.status()
- Количества данных в коллекциях на шардах с отображением среднего количества db.collection.getShardDistribution()
- Частота запросов в (шард, коллекция)

Неравномерное распределение одной из этих метрик явно укажет на необходимость действий по перераспределению данных. Если значение отличается в большую сторону более, чем в 2 раза в течение 10 минут, то стоит считать такой шард горячим.

Дополнительные метрики:
- Потребление ресурсов: CPU, Mem, disk - через zabbix
- Показ причин дисбаланса шардов sh.balancerCollectionStatus()
- Распределение запросов read/write для коллекций

### Перераспределение данных
Механизмы автоматического перераспределения данных:
- Запуск стандартного балансировщика sh.startBalancer() и db.adminCommand({ balancerStatus: 1 }) - для перераспределения чанков между шардами по размеру/количеству данных. 
- Включение поддержки виртуальных шардов: Добавление чанков в коллекцию через reshardCollection, чтобы перераспределить данные между шардами.
- Добавление суффикса к ключу шарда через refineCollectionShardKey 
    - Например, если в этом задании предполагается, что в продуктах был выбран ключ шардирования по категории{category: 1}, то можно использовать ключ {category: 1, _id: "hashed"}. Это позволит уточнить размеры чанков и перераспределить их между шардами через балансировщик или moveChunk.
- Смена ключа шардирования через reshardCollection
- Ввод новых шардов

Механизмы стоит применять от первого к последнему (от самого простого к сложному), пока горячий шард не перестанет быть таковым.

## Текст задания
Из-за категории «Электроника» произошла перегрузка одного из шардов MongoDB, так как 70% запросов приходилось именно на эти товары. Поэтому сейчас нужно разработать стратегию, как выявлять и устранять такие «горячие» шарды, а ещё предложить метрики мониторинга, чтобы в будущем можно было предотвращать такие ситуации. Не забудьте учесть, что товары из популярных категорий могут создавать непропорциональную нагрузку на отдельные узлы.

### Что нужно сделать:

- Разработайте набор метрик, чтобы отслеживать состояние шардов.
- Предложите механизмы автоматического перераспределения данных.
